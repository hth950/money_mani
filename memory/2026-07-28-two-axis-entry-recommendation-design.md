# Design: 개인용 2축 매수 추천과 조건부 모의매수

Generated by office-hours on 2026-07-28  
Status: IMPLEMENTED  
Mode: Builder

## Problem Statement

현재 시스템은 5축 종합점수가 65점 이상이면 `EXECUTE` 후보를 만든 뒤
`PortfolioRiskManager`가 위험 조건을 검사한다. 위험 조건을 넘으면 최종 결정을
`BLOCKED`로 덮어쓰고 `/signals`는 이를 단순 `관망`으로 바꾼다. 그 결과 사용자는
종목의 매수 매력도와 차단된 이유를 동시에 볼 수 없고, 위험을 감수한 개인적
판단이나 조건부 모의매수를 할 수 없다.

2026-07-28에는 SAP·BAC·AAPL이 매수 점수 기준을 통과했지만, 포지션이 1개인
상태에서 신규 종목을 50% 섹터 비중으로 계산하는 기존 규칙 때문에 모두
차단됐다. 이는 `매수 기회 없음`과 `기회는 있으나 정책상 위험함`을 구분하지
못하는 실제 문제다.

## What Makes This Cool

시스템이 사용자를 대신해 예/아니오만 결정하지 않는다. 종목마다 다음 세 가지를
동시에 보여준다.

1. 얼마나 매력적인가: `매수 매력도 0~100`
2. 무엇이 위험한가: `진입 위험도 0~100`과 구성요소
3. 어떤 선택이 가능한가: 매수 추천, 조건부 후보, 관심 후보, 관망/제외

조건부 후보는 경고를 읽고 `위험을 이해했습니다`를 체크한 경우에만 모의매수가
가능하다. 판단 자유도를 늘리되, 사용자가 어떤 위험을 수용했는지 체결 원장에
남긴다.

## Premises

1. 종합점수는 기회 강도이지 포트폴리오 위험 자체가 아니다.
2. 소프트 위험은 정보를 제공하고 선택권을 남겨야 한다.
3. 시세·데이터 무결성 실패 같은 하드 위험은 사용자의 확인으로 우회할 수 없다.
4. 실제 주문은 계속 지원하지 않으며 이번 기능은 개인 모의투자에만 적용한다.
5. viewer는 동일한 정보를 볼 수 있지만 주문과 확인 동작은 할 수 없다.
6. 기존 자동 전략 `positions`, 실계좌 포트폴리오, 모의투자 원장은 서로 섞지 않는다.

## Approaches Considered

### A. 표시만 개선

기존 `BLOCKED`를 유지하고 차단 사유·간단 위험 배지만 노출한다.

- Effort: S
- Risk: Low
- Pros: 빠르고 기존 판정 영향이 작다.
- Cons: 소규모 포트폴리오 차단 문제와 조건부 모의매수 문제를 해결하지 못한다.
- Reuses: `block_reason`, 기존 `/api/signals/actions`.

### B. 기회·위험 2축 모델

기존 종합점수와 별도의 구조화된 진입 위험 평가를 저장하고 최종 표시 등급을
파생한다. 소프트 위험 종목은 조건부 후보가 되며 확인 후 모의매수가 가능하다.

- Effort: M
- Risk: Medium
- Pros: 현재 문제를 직접 해결하고 판단 근거·감사 가능성을 높인다.
- Cons: 위험 산식, DB 스냅샷, 주문 재검증이 필요하다.
- Reuses: `MultiLayerScorer`, `PortfolioRiskManager`, `decision_events`,
  `paper_trades`, 기존 주문 미리보기·idempotency 흐름.

### C. 자산배분 시나리오 엔진

가상 현금, 목표 비중, 주문금액, 손절선까지 입력해 주문 후 포트폴리오를
시뮬레이션한다.

- Effort: XL
- Risk: High
- Pros: 장기적으로 가장 정확한 개인 투자 도구가 된다.
- Cons: 현금 한도가 없는 현재 모의원장과 범위가 충돌하고 MVP가 지나치게 커진다.
- Reuses: 모의 포지션·체결 원장 일부.

## Recommended Approach

접근 B를 구현한다. 기존 점수를 보존하면서 위험을 별도 축으로 추가하고,
조건부 모의매수 확인을 서버에서 강제한다. 자산배분과 현금 기능은 후속 단계로
남긴다.

## Decision Model

### 1. 매수 매력도

기존 `MultiLayerScorer.composite_score * 100`을 그대로 사용한다. 기술·펀더멘털·
수급·인텔·매크로 점수와 가중치도 변경하지 않는다.

### 2. 진입 위험도

`EntryRiskScorer`를 추가하고 0~100으로 계산한다. 높을수록 위험하다.

| 구성요소 | 비중 | 핵심 입력 |
|---|---:|---|
| 포트폴리오 집중 위험 | 30% | 기존/모의 보유, 예상 섹터 비중, 중복 종목 |
| 기술적 타이밍 위험 | 20% | technical score, 추세/과매수·과매도 세부값 |
| 가격 변동성 위험 | 15% | ATR/가격, 최근 60일 변동성 백분위, 갭 |
| 매크로·이벤트 위험 | 15% | macro score, 인텔 신뢰도와 이벤트 임박 여부 |
| 근거 불일치 위험 | 10% | 5축 점수 분산, 전략 합의·다양성 |
| 데이터 품질 위험 | 10% | 가격/재무/수급/인텔 누락 및 데이터 지연 |

각 구성요소는 0~100과 한글 사유를 반환한다. 최종 점수만 저장하지 않고
`risk_breakdown_json`에 입력값·사유·산식 버전을 함께 보존한다.

위험 등급:

- 0~35: 낮음
- 36~60: 보통
- 61~80: 높음
- 81~100: 매우 높음

### 3. 소규모 포트폴리오 집중도

기존 `(같은 섹터 종목 수 + 1) / (전체 포지션 수 + 1)` 계산을 신규 진입의
하드 차단에 사용하지 않는다. 자동 전략 포지션에는 수량·자본 비중이 없으므로
`max_single_weight`를 예상 슬롯 비중으로 사용한다.

```text
예상 신규 포지션 비중 = max_single_weight (기본 20%)
예상 섹터 비중 = (동일 섹터 포지션 수 + 1) × 20%
```

따라서 첫 번째 섹터 포지션은 20%로 허용되고, 두 번째 동일 섹터 포지션은
40%로 위험 경고를 받는다. 실제 주문 미리보기에서는 주문금액과 모의 원가를
사용해 위험도를 다시 계산할 수 있게 확장 지점을 둔다.

### 4. 최종 표시 등급

| 표시 등급 | 기본 조건 | 모의매수 |
|---|---|---|
| `BUY_READY` 매수 추천 | 매력도 ≥65, 위험도 ≤35, 하드 블록 없음 | 확인 없이 미리보기 가능 |
| `BUY_CONDITIONAL` 조건부 후보 | 매력도 ≥65, 위험도 36~80, 하드 블록 없음 | 위험 확인 필수 |
| `EARLY_WATCH` 관심 후보 | 매력도 55~64, 위험도 ≤60 | MVP에서는 불가 |
| `WATCH` 관망 | 매력도 40~54 또는 위험도 >80 | 불가 |
| `AVOID` 제외 | 매력도 <40 | 불가 |
| `UNAVAILABLE` 판단 불가 | 하드 블록 존재 | 불가 |

하드 블록은 모든 시세 소스 실패, 심각하게 지연된 데이터, 잘못된 시장/티커,
거래정지·가격 0, 점수 스냅샷 무결성 실패처럼 주문 자체를 신뢰할 수 없는 경우로
제한한다. 섹터 집중, 기존 자동 전략 포지션, 일일 손실 경고는 소프트 위험으로
내린다.

## Data Model

### scoring_results

다음 필드를 추가한다.

- `opportunity_decision`: 기존 점수만으로 계산한 EXECUTE/WATCH/SKIP
- `risk_score`, `risk_level`
- `risk_breakdown_json`
- `recommendation_tier`
- `hard_block_reason`
- `risk_model_version`

기존 `decision`과 `block_reason`은 호환성을 위해 유지하되 새 화면과 API는 새
필드를 우선 사용한다.

### decision_events

판단 당시의 `risk_score`, `recommendation_tier`, `risk_snapshot_json`,
`risk_model_version`을 append-only로 저장한다. 이후 산식이 바뀌어도 당시 판단을
재현할 수 있어야 한다.

### paper_trades

조건부 매수 체결 시 다음 내용을 변경 불가능한 체결 원장에 저장한다.

- 위험 점수와 전체 위험 스냅샷
- 사용자가 확인한 위험 사유 목록
- `risk_acknowledged_at`
- `risk_acknowledgement_version`
- `risk_snapshot_hash`

## API Changes

### GET /api/signals/actions

기존 필드에 다음을 추가한다.

- `opportunity_score`, `opportunity_decision`
- `risk_score`, `risk_level`, `risk_breakdown`
- `recommendation_tier`
- `hard_block_reason`
- `upgrade_conditions`: 매수 추천이 되기 위해 개선돼야 할 조건

### POST /api/paper-trading/orders/preview

- `BUY_READY`: 기존처럼 처리한다.
- `BUY_CONDITIONAL`: `risk_acknowledged=true`와 현재
  `risk_snapshot_hash`가 필요하다.
- 서버가 위험도를 다시 계산하고 해시가 달라졌으면 HTTP 409로 새 확인을 요구한다.
- `EARLY_WATCH/WATCH/AVOID/UNAVAILABLE`: HTTP 409로 거절한다.

### POST /api/paper-trading/orders

확정 시에도 최신 가격·추천 등급·위험 해시를 다시 검증한다. 확인했던 위험이
변했으면 거래를 반영하지 않고 HTTP 409를 반환한다. 기존 idempotency 동작은
그대로 유지한다.

## UI

`/signals`의 진입 영역을 다음처럼 구성한다.

1. 매수 추천
2. 조건부 매수 후보
3. 관심 후보
4. 관망/제외
5. 기존 매도 추천

각 카드에는 매수 매력도와 위험도 막대를 나란히 표시한다. 조건부 카드에는 상위
위험 사유 3개와 `왜 조건부인가`, `매수 추천으로 올라가려면 무엇이 필요한가`를
표시한다.

조건부 모의매수 흐름:

```text
조건부 모의매수 클릭
→ 위험 구성요소와 현재 스냅샷 표시
→ [ ] 위 위험을 이해했습니다
→ 최신가·비용 미리보기
→ 서버 재검증
→ 모의 주문 확정
```

체크박스는 위험 영역을 펼쳐 끝까지 확인한 뒤에만 활성화한다. viewer에게는
위험 정보만 보이고 버튼·체크박스는 렌더링하지 않는다.

## Scheduling and Refresh

- 일일 스캔에서 기회 점수 계산 후 진입 위험도를 계산한다.
- 09:30/11:30/13:30/15:30/16:10 재스코어링과 인텔 재스코어링에서도 위험도를
  함께 갱신한다.
- 수동 시세 갱신과 주문 미리보기에서는 최신 가격 기반 변동성 위험을 다시 계산한다.
- 일부 데이터 실패 시 마지막 정상 위험 점수는 유지하되 지연 배지와 품질 위험을
  올린다. 시세 전체 실패는 하드 블록한다.

## Configuration

`config/risk.yaml`에 버전된 `entry_risk` 섹션을 추가한다.

```yaml
entry_risk:
  enabled: true
  model_version: v1
  mode: shadow
  low_max: 35
  medium_max: 60
  high_max: 80
  opportunity_execute: 65
  opportunity_early_watch: 55
  assumed_position_weight: 0.20
  weights:
    portfolio: 0.30
    timing: 0.20
    volatility: 0.15
    macro_event: 0.15
    disagreement: 0.10
    data_quality: 0.10
```

## Rollout

1. `shadow` 모드로 위험 점수만 계산·저장하고 기존 추천은 바꾸지 않는다.
2. 최근 20거래일에 새 등급을 재계산해 위험 구간별 5/10/20일 성과를 비교한다.
3. 운영 화면에 위험도와 조건부 후보를 노출하되 주문은 잠시 비활성화한다.
4. 산식과 분포를 확인한 후 `mode: advisory`로 조건부 모의매수를 연다.
5. 문제 발생 시 새 UI/API 분기와 모드만 끄고 기존 decision 필드로 즉시 복귀한다.

## Tests and Success Criteria

- 포지션 1개일 때 첫 번째 알려진 섹터 종목이 50%로 오판되지 않는다.
- 동일 섹터 두 번째 종목의 위험도가 첫 번째보다 높다.
- 매력도/위험도 경계값별 등급이 정확하다.
- 소프트 위험은 조건부 후보, 데이터 무결성 실패는 하드 블록이 된다.
- 조건부 주문은 미확인 시 409, 올바른 확인 시 미리보기 가능하다.
- 확인 후 위험 스냅샷이 변하면 확정 주문이 409가 된다.
- 동일 idempotency key는 한 번만 체결된다.
- 위험 확인 내역과 산식 버전이 paper_trades에 저장된다.
- viewer의 모든 변경 요청은 계속 403이다.
- 실제 KIS 주문 API는 호출하지 않는다.
- 기존 자동 positions·전략 성과·실계좌 포트폴리오 통계가 변하지 않는다.
- 기존 전체 테스트가 통과한다.
- 2026-07-28 데이터 재현 시 SAP·BAC·AAPL이 단순 관망이 아니라 조건부 후보 또는
  명시적 위험 등급으로 설명된다.

## Open Questions

1. 55~64점 관심 후보에도 향후 조건부 모의매수를 허용할지 여부.
2. 위험도 81점 이상을 완전 관망으로 둘지, 이중 확인으로 허용할지 여부.
3. 가상 현금과 목표 포지션 크기를 추가해 섹터 비중을 실제 금액으로 계산할 시점.

MVP 기본값은 1번과 2번 모두 매수 불가로 둔다.

## What I Noticed

사용자는 `추천을 더 많이 보여달라`가 아니라 `보는 사람이 자유롭게 판단할 수
있도록 하자`고 문제를 정의했다. 또한 조건부 행동에는 `위험을 이해했습니다`를
넣자는 안전장치를 직접 선택했다. 따라서 이 기능의 핵심은 추천 개수를 늘리는
것이 아니라, 숨겨졌던 기회와 위험을 분리해 개인 판단의 질을 높이는 데 있다.
